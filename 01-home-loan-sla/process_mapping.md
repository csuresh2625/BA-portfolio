# As-is and to-be process maps (conceptual)

**As-is (simulated):** Application received → document check → if incomplete, request documents → verification → underwriting → decision → manual SLA review.

**To-be (proposed):** Application received → automated completeness checklist → early missing-doc alert → verification → underwriting queue with aging flag → decision → dashboard with branch/channel SLA exceptions → weekly owner review.

**Gap:** Incomplete document detection occurs too late; no agreed stage-level visibility. **Change control:** validate definitions with credit and operations owners before deployment.
